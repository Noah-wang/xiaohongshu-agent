---

## 面向谁
用飞书协作的内容团队、运营小组、产品经理、做技术选型的人。适合那些经常在群里丢链接、事后找不到、想沉淀团队记忆但不想手动整理文档的创作者和小团队。

## 解决的痛点
- 群里刷过的链接转头就沉底，要找的时候只能翻聊天记录。
- 团队资料散落在各个聊天窗口里，没有统一检索入口。
- 做方案对比或选型时，团队内部明明聊过，但没有记录可查。
- 手动整理资料库太耗时，没人愿意长期维护。
- 问 AI 推荐工具，它常常不告诉你出处，或者瞎编。

## Before / After
**Before**：群里分享了一堆链接，过几天想找找不到；做决策时从零搜网页，不知道团队之前试过什么；问 AI 可能得到没有依据的答案。  
**After**：把链接丢给 Mark，它自动读完、摘要、分类、打标签，存到飞书文档；几周后用大白话问它，它只引用团队真正收录过的内容，并附原链接；做决策时先检索内部资料，再脱敏联网补充，保存决策记录，以后还能复盘。

## 核心功能
- **链接自动归档**：发任意链接，它立刻回一张进度卡片，读取后原地更新，最后给出摘要、分类、标签和资料库文档入口。
- **五大来源抓取**：支持 GitHub（含 star 数、语言、许可证）、B 站（含 AI 生成的字幕轨）、YouTube（公开视频字幕轨）、X/Twitter（正文、作者、媒体）、普通文章网页。
- **团队资料库镜像**：收录内容同步到可浏览的飞书 Wiki/docx 文档，聊天回复、列表、删除结果都带资料库入口，团队可以直接翻阅。
- **大白话问答**：可以用自然语言提问，比如“给我推荐一个做 B 站字幕提取的工具”，它检索资料库，只引用团队实际收录过的记录，并附上原链接。
- **决策 Agent**：处理“预算每月 3000 元，帮我选一个社媒监测方案”这类问题，先检索团队资料，再脱敏查询自动联网补充，深入读取候选来源，给出带证据的推荐、备选、风险和下一步。
- **决策中心**：每次决策结论保存到独立的“Mark 决策中心”，之后可以问“上次为什么选它”或“为什么没选另一个方案”，基于当时证据复盘。
- **延迟群提醒+撤回窗口**：私聊收录成功后，可以延迟把同样卡片发到指定飞书群；在可撤回时间内回复“撤回”或“取消提醒”，避免误发链接同步到公开群。
- **记录管理**：直接说“列出最近收录的 10 个项目”即可列出记录；说“把这条删掉+链接”可删除并重新同步文档。
- **文档改写**：说“把文档里的英文改成中文”，它会改写飞书文档里的英文段落。
- **服务器状态查询**：问“看一下服务器状态”，它会报告本机和腾讯云 CVM 指标。

## 典型使用片段
- 用户发一个 X 链接，Mark 立刻回卡片，读取、分析、归档过程中原地更新，最后显示收录完成卡片：摘要“TinyFish 推出的免费网页搜索和页面抓取服务，主打零成本替代 Exa、Tavily、SerpAPI 和 Brave”，分类“AI 工具”，标签“免费 API、网页搜索、AI Agent”，并附资料库文档链接。
- 用户问“给我推荐一个做 B 站字幕提取的工具”，Mark 检索资料库，给出带取舍分析的回答，只引用团队实际收录过的记录，并附上原链接。
- 用户说“预算每月 3000 元，帮我选一个社媒监测方案”，Mark 内部检索、联网研究、比较并保存决策，最终给出推荐方案、候选对比、风险、未知信息和来源，还可以在卡片上点“调整条件”“继续深挖”“换一批方案”“保存决策”。

## 上手门槛
- 需要一台能运行 Node.js 22.19 及以上版本的服务器或电脑。
- 需要一个飞书账号，并创建飞书自建应用，拿到 App ID、App Secret、Verification Token。
- 需要一个可以公开访问的域名和 HTTPS，把飞书事件回调地址指向 `https://<你的域名>/feishu/events`。
- 需要准备一个 OpenAI 兼容接口的 API key，用于摘要和问答；没配的话功能会降级。
- 运行 `npm install` 安装依赖，然后执行开发命令 `npm run feishu:dev`。
- 运行一次性命令创建资料库文档和决策中心文档，并把打印出的 id 填进配置里的 `FEISHU_DOC_ID` 和 `FEISHU_DECISION_DOC_ID`。
- 可选：Monid API key 用于联网搜索；B 站 cookie 用于 B 站字幕；X Bearer Token 用于 X 抓取；腾讯云密钥用于服务器监控。
- 创建飞书文档后默认只有应用自己可见，需要手动打开一次，把自己或群组加成协作者，否则文档点开是空白。

## 已知短板
- B 站字幕抓取会抽风：有时返回一条属于完全无关视频的字幕轨，而且每次请求返回的内容还不一样；多分P视频只抓第一个分P。
- YouTube 如果没有可读字幕，或者服务器 IP 被 YouTube 要求登录验证，只会归档标题、频道、时长和简介，拿不到视频正文摘要。
- 部署门槛不低，不是装个 App 就能用：需要自己准备飞书应用、域名、HTTPS、环境变量、LLM API key。
- 摘要和问答依赖 OpenAI 兼容接口，如果没配或服务商挂掉，会降级到本地启发式规则，回答质量会明显下降。
- 飞书文档初始化容易踩坑：用 tenant token 创建的文档默认只有应用自己可见，忘记手动加协作者的话，点开就是空白。
- B 站字幕需要额外 cookie，X/Twitter 需要 bearer token 才更可靠，否则可能抓不到内容。
- 决策 Agent 有明确步数上限（默认最多 6 至 8 步），候选深入阅读 3 至 5 个，可能不够彻底；关键事实无法验证时会直接说“暂不能给出可靠结论”，不会硬猜。
- 决策 Agent 不会自动执行采购、付款、签约、部署或删除等高影响动作，想让机器人直接下单或操作的不行。
- 资料库本地存储在服务器的 `.knowledge/` 目录里，如果服务器数据丢失，需要依赖飞书文档镜像恢复。

## 可发的帖子选题
- “飞书里丢个链接，自动变资料卡，团队再也不怕链接沉底” —— 主攻核心收录功能，配发链接到生成卡片、飞书文档入口的截图。
- “把‘预算3000选社媒监测方案’丢给飞书机器人，它内部检索+联网调研，还附证据和风险” —— 突出决策 Agent 不是泛泛而谈，有出处、风险和下一步。
- “发错链接到群？这个机器人给你撤回窗口，回‘撤回’就能取消群提醒” —— 讲延迟群提醒+撤回窗口，适合踩坑/尴尬场景。
- “飞书机器人帮你复盘：上次为什么选A不选B？” —— 利用决策中心历史记录，讲团队决策复盘功能。
- “B站/YouTube 视频链接也能自动归档？没有字幕它会照实说，不乱编” —— 聚焦来源处理特点，特别是防止 AI 编造视频内容，建立信任感。
