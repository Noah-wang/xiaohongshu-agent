## 面向谁
- 有 COROS 手表/App，但觉得官方图表不够“会说话”的跑者。
- 愿意自己部署、能看懂一点技术文档的“折腾型”跑步爱好者。
- 想把训练书 PDF、B站跑步视频、自己的 PB/目标/体感结合成训练决策的人。
- 不适合：想开箱即用、不想碰服务器和配置的普通用户——它不是 SaaS，一份部署只对应一个人。

## 解决的痛点
- 通用 AI 只会泛泛回答跑步常识，不知道你的训练负荷、PB、周跑量、体感。
- COROS 官方数据只展示曲线，不给“最近三周是不是练多了”“下一步怎么练”这种判断。
- 训练书和视频知识散落在 PDF、B站收藏夹里，没法自动结合到自己的数据上。
- 想公开分享训练数据给朋友或教练看，又怕别人乱改。
- 主观感受（比如“最近很累”“睡眠差”）数据里看不出来，但训练建议不能没有它。

## Before / After
**Before**  
打开 COROS App 自己翻负荷曲线、恢复状态；翻《丹尼尔斯经典跑步训练法》和收藏的视频，手动判断。去问通用 AI，它只会说“注意恢复”，因为你没告诉它你的全马、半马、周跑量和最近体感。

**After**  
在 Discord 或网页里问一句“我最近三周的训练负荷是不是太高？”，它会自己拉你的 COROS 数据，结合你导入的书/视频知识、长期档案，给出结构化复盘、风险判断和下一步训练建议。运动结束后，它还能等 60 分钟数据稳定，自动推一份复盘到你自己的训练频道。

## 核心功能
每条都能单独当一个帖子卖点。

- **个人数据问答**：你问“最近三周训练负荷是不是太高”，它会拉你的 COROS 训练记录、负荷、恢复状态来回答，不是泛泛讲跑步知识。
- **训练报告自动推送**：运动结束后等 60 分钟数据稳定，自动在 Discord 频道推送报告，包含当前判断、数据依据、下一步训练和边界说明。
- **知识库引用原文**：把训练书 PDF 扔进 `books` 文件夹，或导入 B站视频字幕。问它问题时，它引用来源，展示的就是原文，不自己改写。
- **视频知识自动同步**：订阅 B站 UP 主空间链接，它每半小时自动巡检，单轮最多抓 8 条字幕；发现新视频就存进知识库。视频列表缓存 20 小时，被限流会进入 2 小时冷静期。
- **长期档案与体感记忆**：保存年龄、体重、PB、目标、周跑量，以及“最近很累”“睡眠不好”这类数据看不出的体感。之后的建议会带着这些背景。
- **FIT 原始文件归档**：把 COROS 历史活动的原始文件拉到本地备份。每天约 50 次下载配额，连续 5 条失败会自动停，支持断点续传。
- **公开只读 Web 面板**：可以挂一个公网链接给朋友/教练看训练数据、回答和调用过程。但所有写操作——记录感受、导入视频、改档案——都不开放，防止别人乱改。
- **可选联网搜索**：赛事安排、天气、知识库外的信息可以接 Tavily 或 Brave Search，有每日 50 次搜索预算。
- **教练风格设置**：打开 `/settings` 上传 Markdown（上限 64 KB）改教练语气，自动运动/睡眠报告开关单独控制，下一份报告立即生效，不用重启服务。
- **主 Agent 循环 + 反思**：不是“看一眼你的话就猜一个命令”，而是先调工具、看结果，再决定下一步。回答前还会检查有没有该查没查、该追问没追问的地方。

## 典型使用片段
“用户说什么 → 它做什么”的真实例子：

1. **你问：“我最近三周的训练负荷是不是太高？”**  
   它读取 COROS 活动数据，结合长期记忆、知识库和训练报告流程，给出结构化复盘、风险判断和下一步训练建议。

2. **你问：“我的全马为什么明显慢于半马推算？”**  
   它调出你的全马/半马成绩，用配速计算工具按 Daniels/Gilbert 公式推算，实测和书中 VDOT 配速表误差只有 1~2 秒，再帮你分析差距可能在哪。

3. **你问：“我这个水平该选什么跑鞋？”**  
   它先按“跑鞋”分类缩小知识库范围，再排序，避免把训练理论混进前三条。回答会引用你导入的跑鞋测评视频或书里的内容。

4. **你问：“我一共跑过几场比赛？”**  
   它不会去倒出日常训练流水，而是去照片标注里查比赛记录。如果你从没给比赛照片标注过赛事名，它会查不到或提醒你先补标注。

## 上手门槛
- **服务器**：一台小 VPS 就够，部署通常用 systemd + Caddy 反代，HTTPS 自动签。
- **技术栈**：需要 Python 3.13+ 和 `uv`；接 COROS 数据还需要 Node.js 18+，因为 COROS 官方连接要走 `npx`。
- **模型配置**：最小可跑只需填 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`AGENT_OWNER_NAME`。OpenAI / DeepSeek / Qwen / Kimi / OpenRouter 都能接。
- **COROS 授权**：第一次调用会弹浏览器让你登录 COROS 账号，授权后令牌自动保存。配置里要写死 `COROS_MCP_CLIENT=mcp-remote@0.1.38`，不要用不带版本的写法。
- **Discord 入口可选**：需要 `DISCORD_BOT_TOKEN` 和 `DISCORD_RUNNING_CHANNEL_ID`，写操作只在 Discord 开放。
- **B站视频同步**：需要 B站登录态 `sessdata` / `bili_jct` / `buvid`，放在 `agents/coros_report/config.toml`，这个文件不能提交到仓库。
- **数据备份**：`data/` 目录藏着你所有长期记忆、会话记录、知识库、FIT 文件、照片标注，必须留在服务器上，自己备份，不能提交到公开仓库。

## 已知短板
发“踩坑”“劝退”类帖子全靠这段，尽量挖满。

1. **PDF 表格会丢**。它解析训练书只用文本流，像丹尼尔斯 VDOT 配速表只留下“相同配速、不同距离下消耗的时间”这种标题，表格内容全没了。评测集恰好没考表格题，所以指标看不出来。这是系统最大短板。
2. **网页版只能看不能写**。公开 Web 面板没有登录，所以记录感受、导入视频、改档案全部禁止。想用网页完成日常操作会抓狂，必须回到自己的 Discord 频道或命令行。
3. **首次接 COROS 有版本号坑**。如果配置里写 `mcp-remote` 不带版本号，程序会卡在“正在输入”永远不动。因为授权令牌按版本目录存，`npx` 拉到新版本时目录里没有令牌。必须写死 `mcp-remote@0.1.38`，升级要主动重新授权。
4. **COROS 原始文件下载的“空返回”陷阱**：每天约 50 次配额，用完时接口不报错、只返回空，和“这条活动本来就没有文件”完全一样。脚本连续 5 次失败就停，容易误判成“COROS 只保留 90 天”，其实只是当天额度没了。
5. **B站同步限流很隐蔽**：被限流和 UP 主没发过视频，返回结构一模一样。连续出错会写冷静期文件，接下来 2 小时定时任务直接退出。不能靠提高同步频率硬刚，否则只是把出错代价放大 48 倍。
6. **知识库对视频类内容不太友好**。实测 30 个用例，纯语义检索整体 hit@k 0.97，但视频类命中只有 0.86；混合检索能让视频到 1.00，但书类命中从 1.00 掉到 0.91，总账亏，所以默认关闭。如果你主要存 B站视频，很可能会遇到“明明有视频却查不到”。
7. **知识库会“静默降级”**。如果向量数和块数对不上，系统会自动退回到关键词检索，回答质量下降但不报错，看起来一切正常。常见原因是换了嵌入模型或只给部分内容建了索引。
8. **比赛记录和训练记录是两套数据源**。问“跑过几场比赛”时，它从照片标注里查比赛，训练记录里没有。如果你从没给比赛照片标注过赛事名，它可能答不上或混。
9. **安全策略有时很轴**。同一句话里如果先让 AI 读外部内容（比如搜索报名时间），再要求记录感受，它会在这一轮拒绝所有写入，让你“两件事分开说”。这是为防止外部内容诱导乱写，但用起来有点烦。
10. **它是单人单机工具**。没有多用户、没有登录，一份部署对应一个人的数据。数据都在本地，需要自己备份，误操作或服务器清空就可能丢历史。
