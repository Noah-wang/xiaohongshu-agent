# 去 AI 味（中文小红书版）

方法论骨架来自 [sepia](https://github.com/Nanako0129/sepia)（MIT）。**证据强度要分清**：sepia 的英文词表背后有语料统计和论文（LAMP/CHI 2025、Reinhart PNAS 2025、Russell ACL 2025）；本 skill 的中文词表和句式表是经验归纳，**没有同等强度的证据**，当作启发式清单用，别当判据。

## 最重要的一条：小红书的 register 不是"正式文本"

口语、emoji、语气词、感叹号、「姐妹们」——**这些是小红书的正常语域，不是 AI 味**。

直接套用通用的去 AI 味规则会把文案往正式方向拽，那是另一种翻车。本 skill 的假阳性白名单（见下）优先级高于所有检查项。

## 两段式协议（不可跳过）

1. **先诊断完整**——列出全部缺陷，一条不改
2. **再逐条修**——从最深的层次开始改

顺序不能反。sepia 的原话是：不列清单直接改写，会让 AI 指纹**更明显**而不是更少（在专家检测器上测过）。原因是无清单的改写等于换一批同样机器化的表达。

## 校准原则

| 原则 | 含义 |
|---|---|
| 瞄准区间，别走到反面 | 人类写作各项指标是中等值。把每个 AI 特征都反过来，只会造出一个新指纹——比如刻意写错别字、强行口语化，一眼假 |
| 挑着修，别全改 | 只修清单真正标出来的，不要顺手"优化"其它地方 |
| 留出松弛 | 允许有平淡的句子、没打磨的段落。每一行都锋利本身就是机器特征 |

## 编辑操作配比

**替换 74% / 删除 18% / 新增 8%。** 拿不准就删。

唯一允许增加篇幅的修法是**补充真实的具体细节**——真实的数字、地名、价格、动作。编造的细节比空泛更糟：说错的具体信息是最高级别的破绽。

## 检查清单

一次只跑一项。**AI 味是累积的**——单条命中不算数，扎堆才需要重写。

| # | 检查 | 猎杀目标 |
|---|---|---|
| 1 | 客服腔 | 「希望对大家有帮助」「记得点赞收藏关注哦」「有问题欢迎评论区留言」「以上就是全部内容啦」。删掉——朋友分享东西不这么说话 |
| 2 | 密度 | 同样的内容能不能用一半篇幅说完？放在任何语境下都成立的句子（「随着生活节奏加快」「在这个信息爆炸的时代」）零信息量，删 |
| 3 | 立场 | 该下判断的地方要下。测评没有结论、对比没有推荐、种草没有「我会/不会回购」，是明确的机器特征。真正不确定的地方对冲一次就够，不要每句都对冲 |
| 4 | 具体度 | 价格、时间、地址、型号、用了多久、具体哪一步卡住——要有，而且要真。缺信息就问用户或者留 TODO，**绝不填充** |
| 5 | 排版痕迹 | emoji 机械均匀分布（每段开头一个）；每段字数一样长；什么都分三点；每段结尾都有个总结句 |
| 6 | 结尾残留 | 「总之」「总而言之」「总的来说」「最后」+ 复述前文；空泛展望（「希望大家都能……」）。内容说完就停 |
| 7 | 模板化 | 同一个句式复用三次以上；每个分点的措辞结构完全一致 |
| 8 | 节奏均匀 | 段落和句子长度整齐划一。真人写东西是不均匀的——在乎的地方展开，不在乎的地方一句带过 |
| 9 | 读出来 | 语法没错但没人会这么说。默读一遍，如果这句话你不会对朋友讲，重写成口语句式 |

跑完后做 `references/zh-vocab.md` 和 `references/zh-syntax.md` 的词表/句式扫描。

## 假阳性白名单（优先级最高）

**不要**标记、不要"修复"这些：

| 不是 AI 味 | 原因 |
|---|---|
| emoji、感叹号、语气词 | 小红书的正常语域。删掉反而不像小红书 |
| 「姐妹们」「家人们」「谁懂啊」「救命」 | 平台惯用语。**滥用**（每段都来一次）才是问题，出现本身不是 |
| 话题标签堆在结尾 | 平台格式要求，不是文风问题 |
| 分点排版 | 干货帖本来就该分点，可枚举的内容用列表是对的 |
| 语法正确、没有错别字 | 很多人就是写得干净。故意注入瑕疵是可检测的拙劣手法 |
| 用户本人验证过的口头禅 | 如果这是作者真实的说话习惯，保留 |
| 单个词命中词表 | 只有扎堆才算数 |

## 硬性护栏

- **绝不编造具体信息。** 价格、数据、时间、地点必须来自真实素材。缺就问，缺就留空
- **删优于加。** 唯一的加法是真实的具体细节
- **尊重作者声音。** 有用户历史笔记就先提取他的语言习惯，往那个方向改，而不是往一个通用的"人味"改
- **引用的原话不要动。** 用户评论、产品文案原文保持原样

## 输出格式（诊断模式）

```text
去 AI 味诊断 — <帖子标题>
命中: <#序号 检查项 — 引用原文证据>   (每条一行)
通过: <序号列表>
结论: <干净 / 零星命中 / 扎堆> → <可发 / 局部改 / 重写>
```

诊断完停下。用户说改再改。
